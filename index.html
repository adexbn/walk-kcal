内置两款能力 —— 也可以接你自己的

能力供什么来源
麦当劳门店 + 推荐菜 + 官方精确营养值（158 条，含蛋白 / 脂肪 / 碳水 / 钠 / 钙）麦当劳官方 MCP
高德地图周边任意餐厅 + 网友推荐菜 + 真实路网步行距离高德开放平台
麦当劳的两条通道

① 什么都不用配 —— 用我们内置的官方数据快照（158 条营养值，2026-10-09 抓取）
② 配上 MCD_MCP_TOKEN —— 门店与营养值都实时从 mcp.mcd.cn 拉

只想看个 demo、不想去申请 Token？直接跑就行，效果是完整的。
两款可按需组合，一个环境变量的事：
默认两个都开（合并成一份结果）· WALKKCAL_PACKS=mcd 只看麦当劳 · WALKKCAL_PACKS=nearby 只看周边餐厅

也能接你自己的 —— 点评的企业接口、美团，或者你手上任何一份门店／菜品数据。 数据源是可插拔的：加一个文件 + 一个环境变量，主流程 0 行改动。

跑起来

先跑内置场景 —— 这一步一个 Key 都不需要。

git clone https://github.com/adexbn/walk-kcal && cd walk-kcal
python walkkcal/render.py     # 出图（内置场景，1~2 秒）
open demo/explore.html        # 离线可交互 demo

快照里已经存好了门店、推荐菜、步行距离和热量 —— 麦当劳那 158 条官方营养值也是内嵌的。 Key 只在两件事上需要：抓你自己楼下的点位（高德地图的 AMAP_KEY）、 让麦当劳走实时而非内置快照（MCD_MCP_TOKEN + WALKKCAL_MCD_LIVE=1）。

输出格式是可选的：默认出 SVG —— 浏览器打开就能看、放大不糊，大多数场景够用； 想要 PNG（例如直接发微信、小红书），装一个很小的扩展包即可。

我们诚实地告诉你

额度是你自己定的预算，不是算法塞给你的建议 —— 走路只让它随距离增长。

中餐热量是估算的（平均误差 25–28%），因为语料库里 0% 的菜谱标注了份量。 我们花最大力气的地方不是「算得更准」，而是知道什么时候算不准，然后如实显示「算不出」—— 而不是猜一个看起来正常的数字。

宁可少算，不可算错。
