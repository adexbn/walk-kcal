真的用了麦当劳 MCP

本项目的 MCP 入口对外暴露 4 个工具，它自己内部还会再去调麦当劳官方 MCP—— 打 mcp.mcd.cn 拿回 158 条官方营养值（含蛋白 / 脂肪 / 碳水 / 钠 / 钙）， 与本地中餐估算融合成一个统一结果。

最硬的一条实测证据——同一个坐标，门店变了：

走快照：麦当劳(四川北路店) 1391 m
走实时：麦当劳上海闸北虬江路永兴汇餐厅 792 m
「永兴汇餐厅」本地快照里根本没有——只有真调 MCP 才会冒出来。

内置两款能力 —— 也可以接你自己的

能力供什么
麦当劳门店 + 推荐菜 + 官方精确营养值（158 条，含蛋白 / 脂肪 / 碳水 / 钠 / 钙）
高德地图周边任意餐厅 + 网友推荐菜 + 真实路网步行距离
两款可按需组合，一个环境变量的事：
默认两个都开（合并成一份结果）· WALKKCAL_PACKS=mcd 只看麦当劳 · WALKKCAL_PACKS=nearby 只看周边餐厅

也能接你自己的 —— 点评的企业接口、美团，或者你手上任何一份门店／菜品数据。 数据源是可插拔的：加一个文件 + 一个环境变量，主流程 0 行改动。

跑起来

先跑内置场景 —— 这一步一个 Key 都不需要。

git clone https://github.com/adexbn/walk-kcal && cd walk-kcal
python walkkcal/render.py     # 出图（内置场景，1~2 秒）
open demo/explore.html        # 离线可交互 demo

快照里已经存好了门店、推荐菜、步行距离和热量 —— 麦当劳那 158 条官方营养值也是内嵌的。 Key 只在两件事上需要：抓你自己楼下的点位（AMAP_KEY）、 让麦当劳走实时而非内置快照（MCD_MCP_TOKEN + WALKKCAL_MCD_LIVE=1）。

出图依赖也是可选的：什么都不装 → 出 SVG、退出码仍是 0； 装了 Pillow + pillow_lunasvg → 多一张 PNG。 缺包时自动降级，不会撞 ImportError。

我们诚实地告诉你

中餐热量是估算的，平均误差 25–28%；麦当劳的数据是 MCP 官方精确值。

因为语料库里 0% 的菜谱标注了份量，同一道菜的量级能差 40 倍。 我们花最多力气的地方，不是「算得更准」，而是知道什么时候算不准——然后老老实实显示「算不出」， 而不是猜一个看起来正常的数字。
