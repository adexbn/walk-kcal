麦当劳 MCP 开放的是它自己的营养表。但真实场景里， 你 400 米外那家面馆、那家潮汕火锅多少卡？没有人做这件事。 所以我们把数据源做成可插拔的 —— 麦当劳只是其中一个。 
# packs/pack_yourbrand.py —— 30 行接一个新数据源
from pack_template import BasePack

class YourBrandPack(BasePack):
    name = u'你的品牌'

    def search_stores(self, lon, lat, radius=1500):
        # ① 找店：MCP / HTTP API / 都可以
        return self.mcp.query_nearby_stores(lon, lat, radius)

    def menu_of(self, store):
        # ② 拿菜名：不同 MCP 字段名不一样，适配一下
        return [i['name'] for i in store['menu']]

    def heat_of(self, dish):
        # ③ 算热量：有官方营养表就直接用
        #    没有就走通用估算（份量归一 + 质量闸门）
        return self.nutrition.get(dish) or self.estimate(dish)
写完这个文件，walkkcal 就能识别该品牌的门店， 与麦当劳门店一起参与「按额度排序」。
环节公式说明
基准额度缺口 ÷ 餐次占比 由你设定，不由算法推导
步行消耗MET × 体重kg × 小时 快走 MET 3.5，70kg 约合 4 卡/分钟
新额度基准 + 步行消耗 走得越远，额度越高
排序额度内能吃几道 不是按距离近近排，是按「吃得下几道」排
三个独立的量纲问题必须分别处理：份量（配方做了几份）、 生熟密度（干面 284 卡/100g vs 湿面 120）、 规格（8 寸 vs 10 寸蛋糕，原始数据没标就弃权）。 混用会算出 3 倍误差。
