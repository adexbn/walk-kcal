## 一、零凭证体验

```bash
git clone https://github.com/adexbn/walk-kcal && cd walk-kcal

open demo/explore.html      # ★ 可交互：业态筛选 + 换一批（纯前端，无后端）

```

**两个 demo 都是自包含的** —— 零外链、零依赖、零请求，直接双击也行。

## 二、配 Key 并出图

### 2.1 Key 的唯一入口是配置文件

本项目**绝不把 Key 写进 `.py`**。唯一入口是 `walkkcal/config.py`。

**取值顺序**（前面的优先）：

```
环境变量  >  WALKKCAL_CONFIG  >  <仓库>/config.local.json
         >  walkkcal/config.local.json  >  ../internal/config.local.json
```

格式是 **JSON**（不是 YAML —— 零第三方依赖是硬约束，YAML 要拉 `PyYAML`）。

```bash
cp config.example.json config.local.json     # 模板 → 本地配置（已被 .gitignore 忽略）

python walkkcal/config.py                    # ★ 看当前取值从哪来
# 只报「有没有值」，不打印值本身
```

`config.local.json` **永远不进版本库**；报错文本里的 Key 会被 `config.redact()`
替换成 `<已屏蔽 XXX>`（Key 不会顺着异常信息漏进日志）。

```bash
# 提交前自检：仓库里有没有明文密钥（应无输出）
grep -rnE "[0-9a-f]{32}" --include='*.py' .
```

**需要哪些 Key：**

| Key | 必须？ | 用途 |
|---|---|---|
| `AMAP_KEY` | **是**（出图必需） | 门店搜索 + 路线步行距离 + 地址解析 |
| `MCD_MCP_TOKEN` | 否 | 打开麦当劳**实时**路径（不填则读本地快照，界面会标注快照日期） |
| `BAIDU_AK` | 否 | 只在 `WALKKCAL_GEO=baidu` 时用 |

### 2.2 一步出图（推荐）

```bash
# ★★ 给个地址就行 —— 解析 → 抓数 → 渲染，实测约 16 秒
python walkkcal/shoot.py "上海市黄浦区南京东路100号"
# → out/上海市黄浦区南京东路100号_76fd57.png
#   （没装出图依赖时 → 同名 .svg，浏览器直接打开，效果无损）

python walkkcal/shoot.py "苏州市姑苏区观前街" --city 苏州   # 跨城市必须 --city
python walkkcal/shoot.py "陆家嘴" --radius 1000 --keep-scene
python walkkcal/shoot.py "上海人民广场" --quota 350          # 用户说「这顿只吃 350 卡」
```

| 参数 | 说明 |
|---|---|
| `--city 苏州` | 跨城市消歧（同名地标多的城市**必须**传） |
| `--radius N` | 扫描半径（米），默认 800 |
| `--quota N` | 本餐额度（卡），默认 450 |
| `--out PATH` | 指定输出文件 |
| `--keep-scene` | 保留场景快照（便于离线复渲染） |
| `--no-route` | 用直线距离代替路网距离（快，但额度偏小） |

### 2.3 离线渲染已有场景

```bash
python walkkcal/render.py
# → out/skill_mobile_C.png（纯离线，1~2 秒）

WALKKCAL_DATA=data/k11 python walkkcal/render.py           # 换场景
WALKKCAL_FILTER=西餐 python walkkcal/render.py             # 只看西餐
WALKKCAL_FILTER=快餐 WALKKCAL_PAGE=1 python walkkcal/render.py   # 快餐第 2 批
WALKKCAL_FILTER=咖啡 python walkkcal/render.py             # 咖啡店（默认隐去，点业态即包含）
WALKKCAL_DRINK=1 python walkkcal/render.py                 # 放出「只卖喝的」的店
WALKKCAL_OUT=/tmp/somewhere python walkkcal/render.py      # 换输出目录（默认 out/）
```

⚠️ **不传 `WALKKCAL_DATA` 时读的是 `data/` = 上海·静安虬江路** ——
那是**演示点位，不是用户位置**。

### 2.4 内置 5 个实拍场景

都是真实抓取 + **逐店路网校正**的步行距离：

| 场景 | 位置 | 池 |
|---|---|---|
| 默认 `data/` | 上海·静安虬江路 | 233 家 |
| `data/k11` | 上海·淮海路黄陂南路（K11） | 218 家 |
| `data/jintie` | 上海·普陀近铁城市广场 | 187 家 |
| `data/mchq` | 上海·徐汇西岸麦当劳中国总部 | 185 家 |
| `data/linghelu` | 上海·浦东新区凌河路 | 149 家 |


### 2.6 打开麦当劳实时路径

```bash
# Token 在 https://open.mcd.cn/mcp 申请（登录麦当劳账号 → 激活 → 复制）
# 写进 config.local.json 的 MCD_MCP_TOKEN，或临时用环境变量

WALKKCAL_MCD_LIVE=1 python packs/registry.py
# 会打印：源装配 + 每条渠道的门店来源 + 回退原因
#   · src=mcp        → 走的是官方实时
#   · src=snapshot   → 回退到本地快照，同行写明**为什么**（缺哪个 Key / MCP 报什么错）
```

直连实测证据 → [`../evidence-real.md`](../evidence-real.md)

## 三、出图依赖（唯一的两行）

```bash
pip install -r requirements.txt      # Pillow + pillow_lunasvg
```

| 装了吗 | 结果 |
|---|---|
| 没装 | 出 **SVG**，退出码 **0**，不报错 |
| 装了 | SVG + **PNG** |

**渲染分两步**：① 完整写出 SVG（纯标准库，永远可用）→ ② `Pillow` + `pillow_lunasvg`
把 SVG 位图化（**第 ② 步可选**）。

缺包时**自动降级**，**不会让你撞 `ImportError`**。降级不是故障 ——
业务内容与 PNG **完全一致**，差异只在位图化。
回归测试：`python tests/test_render_fallback.py`

## 四、两条链的口径（改代码前必读）

项目里有**两条独立实施的链路**，改任一侧都要问「另一侧怎么办」：

| 链路 | 入口 | 读哪个文件 |
|---|---|---|
| **文字链** | `packs/registry.py` + `walkkcal/reply.py` + `walkkcal/select.py` | `stores.json`（池子，采集半径 ~1.4km） |
| **图片链** | `walkkcal/render.py`（自建循环） | `detail.json`（明细，采集半径 ~0.8km） |

两个文件的**采集半径本来就不同**，所以全量条数天然对不上 —— **不是 bug**。
要看的是**展示半径内**是否一致。

回归测试：`tests/test_gate.py` 里的 `test_mcd_two_chains_same_source`
（断言两条链在展示半径内必须同源）。改任一侧都要跑一遍。

## 五、环境变量总表

**离线渲染只能靠环境变量** —— `render.py` 没有任何命令行参数。

| 变量 | 作用 | 默认 |
|---|---|---|
| `WALKKCAL_DATA` | 场景数据目录 | `data/`（虬江路） |
| `WALKKCAL_FILTER` | 业态筛选（快餐/西餐/日料/火锅烧烤/咖啡/茶饮…） | 全部 |
| `WALKKCAL_PAGE` | 第几批（每批 15 家） | 0 |
| `WALKKCAL_DRINK` | `1` = 放出「只卖喝的」的店 | 关 |
| `WALKKCAL_CLOSED` | `1` = 放出店名标了「暂停营业」的店 | 关 |
| `WALKKCAL_QUOTA` | 本餐额度（卡） | 450 |
| `WALKKCAL_OUT` | 输出目录 | `out/` |
| `WALKKCAL_PACKS` | 启用渠道：`mcd` / `nearby` / 逗号组合 | 两者都开 |
| `WALKKCAL_GEO` | 地图服务商：`amap` / `baidu` | `amap` |
| `WALKKCAL_CORPUS` | 语料服务商 | 内置 |
| `WALKKCAL_MCD_LIVE` | `1` = 打开麦当劳实时路径 | 关（读快照） |
| `WALKKCAL_CONFIG` | 指定配置文件路径 | 见 §2.1 |
| `AMAP_KEY` / `BAIDU_AK` / `MCD_MCP_TOKEN` | 密钥 | 空 |

## 六、可插拔（换地图 / 换语料 / 换渠道）

**不用改主流程。**

```bash
# 换成百度地图（加一个文件 + 设一个环境变量）
export WALKKCAL_GEO=baidu
export BAIDU_AK=你的key

# 换成大众点评的菜品味型数据
export WALKKCAL_CORPUS=dianping
```

| 你想换 | 要改什么 | 主流程改动 |
|---|---|---|
| **渠道**（启用 / 禁用某个数据源）| 设 `WALKKCAL_PACKS` | **0 行** |
| 地图（高德 → 百度/腾讯） | `providers/geo_xxx.py` 一个文件 | **0 行** |
| 语料（下厨房 → 点评/薄荷） | `providers/corpus_xxx.py` 一个文件 | **0 行** |

**默认启用两个渠道**：麦当劳（官方精确值）+ 周边餐厅（地图 + 语料）。

```bash
WALKKCAL_PACKS=mcd        # 只启用麦当劳
WALKKCAL_PACKS=nearby     # 只启用周边餐厅（即「只要高德」）
```

跑起来会打印一行「源装配」—— **退化会显形，不会静默变空**：

```
源装配：麦当劳(店✓ 菜✓ 热✓官方) ｜ 周边餐厅(店✓ 菜✓ 热✓估算)
```

而且**换语料不会把覆盖率打回原形**：查热量是分层的，
L2（菜名品类）/ L3（门店类型）先验与语料源无关，永远生效。
