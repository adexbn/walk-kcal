| 业态 | 含义 | 备注 |
|---|---|---|
| 快餐 | 汉堡 / 炸鸡 / 披萨 / 中式快餐 | **不往上升**（见下）|
| 小吃 | 生煎 / 锅贴 / 包子 / 卤味 | |
| 面馆 | 拉面 / 米线 / 牛肉面 | |
| **西餐** | **聚合键** = 欧美菜 ∪ 日料 ∪ 韩餐 ∪ 东南亚 | ★ 粗筛 |
| 日料 | 日本料理 | ★ 细筛 |
| 韩餐 | 韩国料理 | ★ 细筛 |
| 东南亚 | 泰 / 越 / 新马 / 印尼 | ★ 细筛 |
| 火锅烧烤 | 火锅 / 烤肉 / 串 | |
| 咖啡 | 咖啡厅 | |
| 茶饮 | 奶茶 / 茶饮 / 茶艺馆 | |
| 面包甜点 | 糕饼 / 蛋糕 / 甜品 | |
| 中餐本帮 | 各地中餐 + 综合酒楼 | |

**「西餐」的口径是世俗逻辑，不是分类学**：
> 西餐 = 非中餐的**正餐**。含欧美菜/日料/韩餐/东南亚；
> **不含**快餐/小吃/面馆/火锅/咖啡/茶饮/甜点/中餐。

**★ 快餐不往上升**：快餐本身分中式/西式，但**我们只做到「快餐」这一层**，
不再往下分。所以 **麦当劳 = 快餐，不是西餐**。

## 二、判定三层（贡献从大到小）

| 层 | 依据 | 谁供给 | K11 218 家的贡献 |
|---|---|---|---|
| **①** | `store['industries']` | ★ **地图 provider 翻译好** | **171 家次** |
| **②** | `category_hint` / `keytag` | 数据源自带（通用字段）| 看数据 |
| **③** | 店名关键词 | 本仓库内置（品牌识别）| 61 家次 |

**三个层是「或」的关系，可叠加**（一家店可能同时有日料 + 面馆标签）。

## 三、★ 关键：高德的知识**不在** `filter.py` 里

以前 `filter.py` 里直接写着高德的类目名（`'外国餐厅'`、`'快餐厅'`），
这是个坑：

> **换百度 → 这 20 条规则全废 → 覆盖率 82% → 28%**

现在拆成两层：

```
walkkcal/providers/geo_amap.py    ← 高德类目 → 业态（高德专属知识）
        ↓ 产出统一的 industries 字段
walkkcal/filter.py                ← 只认归一化词表，不认识任何服务商
```

**各家的类目体系完全不一样**：

| 服务商 | 原始类目长这样 | 翻译在哪 |
|---|---|---|
| 高德 | `餐饮服务;外国餐厅;日本料理` | `geo_amap.industries_of()` |
| 百度 | `美食;日本料理` | `geo_baidu.industries_of()` |
| 你的 | 随便什么 | `geo_template.py` 抄 20 行 |

**三条输出**（都对）：

```python
geo_amap.industries_of(u'餐饮服务;外国餐厅;日本料理')  # → ['日料']
geo_apm .industries_of(u'餐饮服务;中餐厅;火锅店')      # → ['火锅烧烤']
geo_baidu.industries_of(u'美食;日本料理')             # → ['日料']
```

**报不出来就返回 `[]`**（合法）—— 上层会退到 ②③ 兜底。
**但不要瞎猜**：猜错会污染筛选，比留空更糟。

回归测试里有一条架构断言守着这件事：

```python
check(u'★filter 不认识高德 type',
      F.classify({'type': u'餐饮服务;外国餐厅;日本料理'}), [])
```

## 五、已知边界（都不是 bug）

| 现象 | 原因 | 处理 |
|---|---|---|
| `西贡妈妈SaigonMama·越南料理` 高德标成 `广东菜(粤菜)` | **高德自己标错** | keytag「东南亚菜」+ 店名「越南」救回 |

## 六、踩过的三个坑（都有回归测试）

1. **`atag` 是推荐菜名列表，不是品类**
   拿它判业态 → 「Tims咖啡」的 `atag` 含「美式咖啡」→ 被归成「美式西餐」。

2. **聚合键被算两遍**
   「西餐」既是**细标签**（欧美菜）又是**聚合键**，
   `counts()` 里两遍都累加 → 真值 21 家被算成 29 家。

3. **三级类目别再套二级伞**
   `外国餐厅 → 西餐` 无条件叠加，会让日料店同时被打上「西餐」。
   拆成「三级优先 + 二级兜底」后由 `GROUPS` 显式表达聚合。
