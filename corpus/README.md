# corpus/ · 语料

**这里是「菜名 → 一份多少卡」的成品表**（`local_dish_heat.json`）。
它由下方的原始语料离线算出，随仓库一起下发 —— 几百 KB 以内。

## 为什么这里只有一张小表

| | 规模 | 在仓库里？ |
|---|---|---|
| 原始语料（下厨房公开食谱集） | **1.9 GB** · 152 万道食谱 | ❌ **不下发** —— GitHub 单文件限 100 MB，而且运行时根本不需要 |
| **本目录的成品表** | 几百 KB | ✅ 随 `git clone` 下发 |

原始语料只在**开发期**用一次：跑 `walkkcal/batch_heat.py`，把食谱逐条算成
「一份的热量」（含份量归一化 + 质量门），结果写进本目录。

## 表里的数字是怎么来的

```
1.9 GB 原始语料（食谱 → 配料 → 克数）
   ├─ batch_heat.py    一批扫完所有目标菜（不是每道菜扫一遍 1.9 GB）
   ├─ portion.py       ★ 把「整份配方的热量」换算成「一人份」
   └─ quality_gate.py  可疑值直接丢，不进结果
        ↓
   corpus/local_dish_heat.json          ← 本目录
        ↓
   walkkcal/providers/corpus_xiachufang.py   ← 每道菜查这张表
```

★ `portion.py` 为什么关键：下厨房语料的**结构化字段里没有份量**
（少数菜谱正文会写「2 人份」，但标准不统一、比例也低，本项目未采用），
直接把「配方总热量」当「一份」会错两个数量级
（小馄饨算出 43 卡、肉夹馍算出 1961 卡）。它用「配料克数 ÷ 单份标准量」
反推份数，再取所有配料里的最大值 —— 详见 [`walkkcal/portion.py`](../walkkcal/portion.py)。

## 表里查不到的菜怎么办

会走**分层估算**，并在结果里如实标成「估算」而不是精确值：

```
① 查这张表（精确，误差 ±25%）
② 剥掉修饰词再查一次（「云海肴汽锅鸡」→「汽锅鸡」）
③ 查品类先验（含「面」→ 面食类典型值）
④ 看门店业态（咖啡厅 → 饮品档）
⑤ 都判不出 → 显示「算不出」，不猜
```

## 加自己的语料源

放一张 `{"菜名": 卡数}` 的 JSON 到这个目录，照
[`walkkcal/providers/corpus_template.py`](../walkkcal/providers/corpus_template.py)
抄 20 行即可 —— 详见 [`docs/扩展开发.md`](../docs/扩展开发.md)。
